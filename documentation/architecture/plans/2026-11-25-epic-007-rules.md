# EPIC-007, règles de configuration (US-007-06) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** des règles de configuration déclaratives (YAML, sur les clés du format d'export), embarquées et extensibles par l'organisation, appliquées par un moteur du domaine à chaque écriture du shell et à l'ouverture d'un realm.

**Architecture :** un moteur pur dans `domain.definition.rules`, qui évalue des règles sur une vue à plat des clés d'un élément (`ElementKeys`). Le port `RealmDefinitions` fournit cette vue, calculée par l'adaptateur de fichiers avec la traduction modèle → clés qu'il a déjà, et écrit les clés posées par les règles. Les fichiers de règles et le realm de référence de Keycloak sont lus dans `infrastructure.source.rules` ; le shell affiche les verdicts.

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4, SnakeYAML 2.5, Jackson 2.20.

**Spec :** [ADR-009](../ADR-009-regles-de-configuration.md) (la décision), [ADR-008](../ADR-008-shell-edition-des-definitions.md), [EPIC-007](../epics/EPIC-007-shell-edition.md) (US-007-06).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

## Points de revue

1. **Une désactivation dont l'identifiant a une faute de frappe** fait échouer le démarrage du shell avec le code `2`, en nommant l'identifiant inconnu, au lieu de laisser la règle active en silence → tests des tâches 3 et 8.
2. **Un client écrit à la main avec une URI `*`, dont on ne change que la description**, est écrit ; la non-conformité est rappelée, pas bloquante → test de la tâche 7.
3. **Une URI `{{appUrl}}/*`** n'est ni refusée ni signalée comme non conforme par `client.redirect-uris.no-wildcard` : elle est non vérifiable → test de la tâche 2.
4. **Un nouveau client `spa` sans attribut PKCE** reçoit `S256` par la valeur par défaut et passe la règle ; le même client modifié à la main sans PKCE, puis réécrit, est bloqué seulement si la modification a retiré l'attribut → tests de la tâche 7.
5. **Une valeur par défaut booléenne** (`frontchannelLogout: true`) est écrite comme un booléen, sans guillemets, en YAML comme en JSON → test de la tâche 5.
