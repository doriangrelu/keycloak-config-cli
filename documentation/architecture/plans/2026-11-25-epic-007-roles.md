# EPIC-007, rôles (US-007-08) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** créer des rôles de realm ou de client, modifier leur description et les lister depuis le shell, avec les règles de configuration appliquées.

**Architecture :** comme pour les clients (US-007-07) : deux cas d'usage dans `application.definition` (`CreateRole`, `EditRole`) posent les questions par le port `Questions` et écrivent par `SaveElement` ; les commandes `role …` de `infrastructure.cli.shell` lisent les options et affichent le résultat avec `SaveResultLines`.

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4.

**Spec :** section US-007-08 de l'[EPIC-007](../epics/EPIC-007-shell-edition.md) (décisions du 25/11/2026), [ADR-008](../ADR-008-shell-edition-des-definitions.md), [ADR-009](../ADR-009-regles-de-configuration.md).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

## Contraintes globales

- Celles des plans précédents (licence, `spotless:apply`, ArchUnit, placeholders entre guillemets, anglais pour le code et la doc utilisateur, français pour l'architecture, aucune mention d'ADSN).
- Branche `feature/US-007-08-roles`. Commits au nom de `Dorian GRELU <doriangrelu839@gmail.com>`. Fin de story : `./mvnw -B verify` vert avec Docker (hors les 20 erreurs MockServer connues), fusion, push `origin` et `adsn`, « Réalisé » dans l'EPIC.
- Mode script (décision de l'utilisateur, US-007-07) : une question sans réponse prend sa valeur proposée et n'échoue (code `2`) que sans proposition.
- Textes : question `Role of` ; choix `The realm` — `a role every client can give`, puis `Client '<id>'` — `a role of this client` ; questions `Name`, `Description`.

## Points de revue

1. **Un nom déjà pris au même endroit** est redemandé en session et fait échouer le script (code `2`) ; le même nom pour un autre client ou pour le realm est accepté → tâche 1.
2. **Le premier rôle d'un client** qui n'en avait pas demande confirmation, même si le realm a déjà des rôles de realm → tâche 1.
3. **`role edit` ne change jamais le nom** : `--name` y est refusé (code `2`) → tâche 3.
4. **Un client créé par Keycloak** (`realm-management`) n'est jamais proposé ni accepté par `--client` → tâches 1 et 3.
5. **`role create` sans `--client` en mode script** crée un rôle du realm → tâche 3 (test par le vrai lanceur).
