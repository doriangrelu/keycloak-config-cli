# EPIC-008, extraction d'un realm (US-008-04) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** `realm extract <realm>` lit un realm configuré à la main sur la cible connectée et crée un nouveau dossier de realm, normalisé et découpé, qui s'importe tel quel ; les secrets deviennent des variables ; un dry-run lancé juste après n'annonce aucun changement.

**Architecture :** la `Connection` de la cible (adaptateur Keycloak) lit l'export partiel du realm, le normalise avec le moteur de l'EPIC-005 (realm de référence de la version de la cible), remplace les secrets masqués par des placeholders et rend un **document neutre** (JSON) avec la liste des variables et les avertissements de la normalisation ; elle sait aussi lire les secrets actuels des clients. Le port `RealmDefinitions` (adaptateur des fichiers) écrit ce document découpé selon `StandardLayout`. Le cas d'usage `ExtractRealm` relie les deux ; le shell ouvre ensuite le realm extrait et garde les secrets des clients dans la mémoire de la session (décision de l'utilisateur, option A).

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4, Keycloak 26.5.3 (admin client), Jackson 2.20, SnakeYAML 2.5, Testcontainers.

**Spec :** [ADR-010](../ADR-010-shell-mode-connecte.md) (« Extraction d'un realm : `realm extract` », « Précisions » : lecture du realm, ce qui est écrit, extraction), [EPIC-008](../epics/EPIC-008-shell-connecte.md) (US-008-04), EPIC-005 (normalisation), US-007-11 (`StandardLayout`).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

- **La normalisation en ligne de commande (`run.operation=NORMALIZE`) et l'import gardent exactement leur comportement** et leurs tests (aucun test existant modifié dans ses assertions).
- **Commande** : `realm extract <realm> [--folder <dossier>] [--format yaml|json] [--with-users]`, connecté seulement (`Not connected: use 'connect <target>'`, code `2`). Dossier par défaut : le nom du realm ; mêmes vérifications que `realm create` (nom portable, aucun dossier existant, même avec une autre casse : refus, code `2`, rien écrit). Format par défaut : `yaml`. Realm absent de la cible : `Realm '<realm>' not found on <cible>`, code `4`.
- **Lecture** : export partiel de l'API d'administration (`partialExport`, groupes, rôles et clients compris), normalisé par le moteur de l'EPIC-005 (`RealmExportReader`, `RealmNormalization`, `RealmExportWriter`) avec le realm de référence de la version de la cible, sinon la version de référence la plus proche (comme la normalisation). Tout le realm est extrait ; un type entièrement par défaut n'est pas écrit.
- **Utilisateurs** (`--with-users` seulement) : lus par l'API, avec `username`, `enabled`, `email`, `emailVerified`, `firstName`, `lastName`, `attributes`, `requiredActions`, `realmRoles`, `clientRoles`, `groups` ; jamais d'identifiant, de date, ni de mot de passe ou d'autre `credentials`. Les utilisateurs venant d'un annuaire (`federationLink`) et les comptes de service (`serviceAccountClientId`) sont écartés ; leur nombre est signalé s'il n'est pas nul.
- **Secrets → variables** (jamais une valeur écrite, affichée ni journalisée) :
  - secret d'un client confidentiel : la variable que propose le shell (US-007-07, `SecretVariables.proposedFor` : `shop` → `{{shopSecret}}`) ;
  - secret d'un fournisseur d'identité (`config.clientSecret`) : `{{<alias>ClientSecret}}` ;
  - mot de passe SMTP (`smtpServer.password`) : `{{smtpPassword}}` ;
  - identifiant d'un composant (`config.bindCredential`, LDAP) : `{{<nom du composant>BindCredential}}` ;
  - les noms suivent la même mise en forme que `SecretVariables` (camelCase, séparateurs retirés) ; deux secrets qui auraient le même nom reçoivent un suffixe `2`, `3`…
- **Fichiers** : découpés selon `StandardLayout` (`00-realm`, `20-clients`, `30-roles`, `40-groups`, `50-links`, clé `realm` dans chaque fichier, types non nommés dans `00-realm`), dans le format choisi, listes triées comme le fait la normalisation, placeholders écrits entre guillemets ; le dossier est écrit en entier ou pas du tout (calcul en mémoire, puis écriture).
- **Sortie** : `Realm '<realm>' extracted to <dossier>/: <fichiers séparés par ", ">`, puis, s'il y en a, `Variables to give at import: <noms triés séparés par ", ">`, puis les avertissements de la normalisation (`Default <type> '<clé>' was deleted in Keycloak: an import may bring it back`), puis `<n> users from a directory or service accounts not extracted` si utile ; enfin le realm est ouvert (`Realm '<dossier>' opened`, comme `realm open`).
- **Secrets des clients en mémoire (décision de l'utilisateur, option A)** : après l'écriture, les secrets actuels des clients confidentiels sont lus par l'API et rangés dans la mémoire de la session (`VariableValues`) sous le nom de leur variable, pour le realm ouvert et la cible connectée ; ils ne sont ni écrits ni affichés, et `Variables to give at import` ne liste alors que les autres variables, suivies de `(client secrets read from <cible> and kept for this session)` quand il y en a. Les autres secrets (fournisseurs d'identité, SMTP, LDAP) restent illisibles : ils sont listés.
- **Règles** : l'extraction ne vérifie pas les règles de l'organisation (ADR-009) ; `realm open` les signale comme pour tout realm.
- **Critère de l'ADR** : sur la même cible, juste après l'extraction, `realm dry-run` avec les variables listées données à leur valeur actuelle annonce `Dry run: no change pending.`
- L'ADR-010 est mis à jour (« Précisions », point « Extraction ») : la commande ouvre le realm extrait et garde les secrets des clients en mémoire (option A), au lieu de « la commande n'ouvre pas le realm ».

## Points de revue

1. **Aucun secret écrit, affiché ou journalisé** : les fichiers, la sortie et les journaux ne contiennent ni le secret d'un client, ni celui d'un fournisseur d'identité, ni le mot de passe SMTP, ni `**********` (le masque de Keycloak) → tâches 2 et 3.
2. **Le dry-run juste après n'annonce aucun changement**, sur un realm qui a des clients (dont un confidentiel), des rôles du realm et de client, des groupes, un fournisseur d'identité avec secret, un serveur SMTP avec mot de passe, et des réglages modifiés → tâche 3 (IT Keycloak).
3. **Rien n'est perdu au découpage** : l'union des clés des fichiers écrits est égale au document extrait → tâche 1.
4. **Un dossier existant n'est jamais touché**, et un échec (Keycloak injoignable, realm absent) n'écrit rien → tâches 1 et 3.
5. **La normalisation en ligne de commande** produit exactement le même fichier qu'avant → tâche 2.
