# EPIC-007, groupes (US-007-09) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** créer des groupes (et sous-groupes) avec leurs rôles, modifier leurs rôles et afficher l'arborescence depuis le shell, avec les règles de configuration appliquées.

**Architecture :** comme pour les clients et les rôles : `CreateGroup` et `EditGroup` dans `application.definition` posent les questions par le port `Questions` (qui gagne `chooseMany`) et écrivent par `SaveElement` ; un catalogue des rôles possibles (`RoleCatalog`) réunit les rôles du dossier et ceux de Keycloak ; les commandes `group …` de `infrastructure.cli.shell` lisent les options et affichent le résultat.

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4.

**Spec :** section US-007-09 de l'[EPIC-007](../epics/EPIC-007-shell-edition.md) (décisions du 25/11/2026), [ADR-008](../ADR-008-shell-edition-des-definitions.md), [ADR-009](../ADR-009-regles-de-configuration.md).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

- Celles des plans précédents (licence, `spotless:apply`, ArchUnit, placeholders entre guillemets, anglais pour le code et la doc utilisateur, français pour l'architecture, aucune mention d'organisation ni de projet interne).

- Mode script : une question sans réponse prend sa valeur proposée et n'échoue (code `2`) que sans proposition.
- Textes : `Name` ; `Parent group` avec `None` — `a top-level group` (proposé) puis un choix par chemin (`/team`, explication `a subgroup of this group`) ; `Roles`. Un rôle de client s'écrit `client/role` dans la liste et dans `--client-roles`.

## Points de revue

1. **Un chemin déjà pris** (`/team/devs` existe) est redemandé en session et fait échouer le script ; le même nom sous un autre parent est accepté → tâche 2.
2. **Les rôles de Keycloak** (`offline_access`, `realm-management/view-users`) sont proposés après ceux du dossier, marqués `(Keycloak)` ; `default-roles-<realm>` n'apparaît que pour un nom de realm littéral → tâche 2.
3. **Une réponse `1,9` hors de la liste** est redemandée en session ; `-` donne aucun rôle ; Entrée garde les rôles proposés → tâche 1.
4. **`group edit` ne déplace ni ne renomme** : `--name` et `--parent` sont refusés (code `2`) → tâche 4.
5. **Un sous-groupe dont le parent est déclaré dans un autre fichier** que `40-groups` : l'écriture ne casse pas (ou refuse clairement) → tâche 2 (test sur le vrai adaptateur).
