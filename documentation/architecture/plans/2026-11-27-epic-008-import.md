# EPIC-008, dry-run et import du realm ouvert (US-008-02) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** connecté à une cible, `realm dry-run` affiche ce que l'import des fichiers du realm ouvert changerait, et `realm import` l'applique après confirmation ; les variables des fichiers sont données par `--var`, par `KCC_VAR_<NOM>`, par leur valeur par défaut, ou demandées.

**Architecture :** le cas d'usage `ImportOpenedRealm` (`application.definition`) compose deux ports, comme l'exige ArchUnit (l'adaptateur Keycloak ne voit pas celui des fichiers) : `RealmDefinitions.importFiles` (implémenté dans `infrastructure.source`) lit les fichiers du dossier et rend leurs placeholders avec les valeurs résolues ; la `Connection` de la cible (implémentée dans `infrastructure.keycloak.connection`) simule ou applique ces fichiers avec le pipeline `ImportRealms` existant, construit dans le contexte Spring de la cible. Le cas d'usage `ResolveVariables` donne une valeur à chaque variable. Le shell affiche le plan avec `DryRunReport`.

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4, Mustache (JMustache, déjà utilisé par l'import), Keycloak 26.5.3, Testcontainers.

**Spec :** [ADR-010](../ADR-010-shell-mode-connecte.md) (« Import et dry-run du realm ouvert », « Précisions » : import et dry-run, variables, codes de sortie), [EPIC-008](../epics/EPIC-008-shell-connecte.md) (US-008-02), [ADR-004](../ADR-004-moteur-de-reconciliation.md), [ADR-005](../ADR-005-erreurs-et-codes-de-sortie.md).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

- Fichiers importés : ceux que lirait `import.files.locations=<dossier du realm ouvert>` (mêmes exclusions, fichiers cachés ignorés, triés par nom), avec les options d'import par défaut (`import.validate`, `import.behaviors.*` à leur valeur par défaut). Pas de réglage des options d'import depuis le shell.
- **Résolution d'une variable**, dans cet ordre : `--var nom=valeur` de la commande ; la valeur gardée en mémoire par la session ; la variable d'environnement `KCC_VAR_<nom>` (nom tel qu'écrit, sans changement de casse) ; la valeur par défaut écrite dans le placeholder (`{{nom:défaut}}`) ; sinon la question `Value of '<nom>'`, sans écho quand le nom contient `secret` ou `password` (casse ignorée). En mode script, une variable sans valeur fait échouer la commande avec le code `2` et le message `Variable '<nom>' has no value: give it with --var <nom>=… or KCC_VAR_<nom>`. Une variable utilisée avec deux valeurs par défaut différentes prend celle du fichier qui l'utilise (le rendu Mustache le fait déjà) : la résolution ne la force pas.
- **Mémoire des valeurs (décision de l'utilisateur, option A)** : les valeurs données par `--var` et les réponses aux questions sont gardées par la session, en mémoire seulement, pour le realm ouvert et la cible connectée ; elles sont oubliées à `realm open`, `realm create`, `connect`, `disconnect` et à la sortie. Jamais écrites, affichées ni journalisées.
- `--var` : répétable, `nom=valeur` (la valeur peut contenir `=` ; un nom vide ou sans `=` → code `2`, message `Invalid --var '<nom>': expected name=value` sans la valeur).
- **Textes** :
  - `realm dry-run` : `Dry run of '<dossier>' on <cible> (<url>)`, puis le texte de `DryRunReport.toText()` (lignes `+`, `~`, `-` et `Dry run: no change pending.` ou `Dry run: <n> change(s) pending.`).
  - `realm import` : `Import of '<dossier>' on <cible> (<url>)`, les lignes du plan, puis, s'il est vide, `Nothing to import` (rien n'est appliqué) ; sinon la question `Apply these <n> change(s) to <cible>?` (non par défaut), puis `Realm '<realm>' imported on <cible>: <n> change(s) applied` ou `Nothing written`. En mode script sans `--apply` : `Nothing written: run again with --apply`, code `0`.
  - Sans connexion : `Not connected: use 'connect <target>'` (code `2`) ; sans realm ouvert : le message existant de `NoRealmOpenedException` (code `2`).
- **Codes de sortie** (ADR-005) : `realm dry-run` en mode script → `10` s'il reste des changements, `0` sinon ; dans un script (`shell.script`), un code `10` n'arrête pas le script, et le script se termine avec `10` si aucune commande n'a échoué et qu'au moins un dry-run a trouvé des changements. Fichier invalide → `2` ; Keycloak injoignable → `3` ; refus de Keycloak → `4`.
- **Secrets** : aucune valeur de variable dans une sortie, un journal ou un message d'erreur (le plan ne liste que des noms de champs). Les tests le vérifient avec une valeur repérable.

## Points de revue

1. **Le dry-run n'écrit rien** sur la cible, même pour un realm absent (le realm n'est pas créé) → tâches 3 et 4.
2. **Un import refusé à la confirmation n'écrit rien** ; un `realm import --apply` suivi d'un `realm dry-run` annonce `no change pending` → tâches 3 et 4.
3. **Une valeur de secret ne fuit pas** : ni dans la sortie, ni dans un message d'erreur (par exemple un fichier invalide après rendu), ni dans les journaux → tâches 1, 2 et 4.
4. **La mémoire de session** est bien oubliée en changeant de realm ou de cible : un `connect` vers une autre cible redemande la variable → tâche 4.
5. **L'import en ligne de commande** fonctionne exactement comme avant (beans du contexte principal inchangés) → tâche 3.
