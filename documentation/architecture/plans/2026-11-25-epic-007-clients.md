# EPIC-007, clients (US-007-07) — plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent des cases à cocher (`- [ ]`).

**Objectif :** créer, modifier et lister les clients d'un realm depuis le shell, avec des questions guidées, les règles de configuration (ADR-009) appliquées et leur verdict affiché.

**Architecture :** deux cas d'usage dans `application.definition` (`CreateClient`, `EditClient`) posent les questions par le port `Questions`, construisent un `ClientDefinition` et l'écrivent par `SaveElement`, qui applique déjà les règles. Les commandes `client …` de `infrastructure.cli.shell` lisent les options, appellent les cas d'usage et affichent le résultat.

**Stack :** Java 25, Spring Boot 4.0.2, Spring Shell 4.0.4, SnakeYAML 2.5, Jackson 2.20.

**Spec :** section US-007-07 de l'[EPIC-007](../epics/EPIC-007-shell-edition.md) (décisions du 25/11/2026), [ADR-008](../ADR-008-shell-edition-des-definitions.md) (modèle, types d'application, questions guidées), [ADR-009](../ADR-009-regles-de-configuration.md) (règles).

Package racine : `io.github.doriangrelu.keycloak.config` (`...` ci-dessous).

- Branche `feature/US-007-07-clients`. Commits au nom de `Dorian GRELU <doriangrelu839@gmail.com>`. Fin de story : `./mvnw -B verify` vert avec Docker démarré (hors les 20 erreurs MockServer connues sous Windows), fusion, push `origin` et `adsn`, section « Réalisé » de l'EPIC.
- Libellés du choix du type (anglais, ordre fixe) : `Front-end application (SPA)` — `runs in the browser, cannot keep a secret` ; `Web application with a server` — `the secret stays on the server` ; `Service to service` — `calls other services with its own rights, no user` ; `API` — `receives tokens, logs nobody in`.
- Noms des types en option et à l'affichage : `spa`, `web-application`, `service`, `api` (et `custom` à l'affichage).
- Une commande sans réponse possible en mode script échoue (`MissingAnswerException`, code `2`).

## Points de revue

1. **Un identifiant de client déjà pris** est redemandé en session et fait échouer la commande en mode script (code `2`), sans rien écrire → tâche 3.
2. **Un secret écrit en dur** (`--secret abc123` ou la réponse `abc123`) est refusé ; seule une valeur entièrement variable (`{{x}}`) ou `none` est acceptée → tâches 3 et 5.
3. **Une URL variable** (`{{appUrl}}`) donne les propositions `{{appUrl}}/*` et `{{appUrl}}`, écrites entre guillemets → tâche 3.
4. **Modifier la description d'un client « personnalisé »** ne touche ni à ses flows ni à ses autres clés → tâche 4.
5. **Le premier client d'un realm qui n'en déclarait pas** demande confirmation en session, et échoue en mode script sans `--declare-type` → tâches 3 et 5.
